# 系统功能说明(自描述)

## 一句话

管理端「系统设置 → 系统功能说明」页面:罗列项目的设计框架与功能逻辑。
数据源 = 仓库内 `cogni_agent/feature_docs/` 下的 markdown,**随镜像发布、
请求时实时读文件**——改文档重新部署即生效,无缓存无版本表,纯只读不写库表。

**描述对象是代码,代码是唯一真实源**:本清单里的每篇都是「代码当前行为」的
确定性描述(派生结果),不写过程、不写计划、不写「当时怎么想的」;写下的每一句
都必须能对着代码逐条核对。

## 内容组织

```
cogni_agent/feature_docs/
├── feature_docs.md            ← 本篇(清单自身的 meta 说明,放根目录)
├── 框架/                       ← 顶级一:框架级(机制/基座,与具体业务无关)
│   └── 调度/                  ← 二级:一类文档的归类名
│       └── cron_scheduler.md      定时任务心跳调度体系
└── 业务/                       ← 顶级二:业务级(具体业务能力)
    └── APP数据预热/
        └── prewarm.md              APP 端数据预热体系
```

**命名与归类原则**:
- **顶级只分两类**:`框架/`(跨业务的机制与基座——调度、鉴权、任务队列
  这类,换了业务它们还在)与 `业务/`(具体业务能力——APP 数据预热、
  景区数字大脑这类)。判断标准:这块东西换个业务还成立吗?
- **二级 = 一类文档的归类名**(类目词,如「调度」「知识」),不是某个功能名
  ——目录装的是一组同域文档,不是单篇;名字要具体到不看正文能猜到范围
- **层级约定两级**,但**机制不限**:树构建与渲染均递归,三级四级目录零代码
  改动自动支持(再深通常说明分类本身要重构)
- 后端 `rglob` 递归扫描,返回 `directory` 字段(完整相对路径,如 `框架/调度`);
  doc_id 含目录段,字符白名单(字母/数字/_/-/中文)+ `is_relative_to` 双重防
  路径穿越;详情路由用 `:path` 转换器接住多段 id
- 前端左侧按目录渲染折叠树(框架/业务/通用排序固定),搜索时自动展开,
  详情页显示目录面包屑

## frontmatter 元数据

```yaml
---
title: 文档标题(缺省=文件名)
category: 分类徽章(展示用,如 调度/预热)
summary: 一句话摘要(列表卡片副标题,也作为搜索词)
related: 关联代码文件路径(逗号分隔,行为级改动时需同步更新本文档)
---
(正文 markdown)
```

## 写文档的规矩

1. **每个功能一篇**:机制、架构、语义、边界、参数口径,给未来的自己/接手人看
2. **只写「现在是什么样」**,判断标准是「这句能对着代码核对吗?」——
   机制/数据模型/判断分支/参数含义/边界与例外照写;**计划、阶段、评审、TODO、
   待实施、日期沿革、「后续将…」「当时考虑过…」一律不写**(那些属于任务期
   文档或 commit message,任务结束即消失)
3. **不引用 `docs/` 下的文档**(过程区,随时会被删):要那个结论就内联成一句话。
   本篇只允许引用:代码路径、配置项、接口路径、迁移号
4. **写不出对应代码的功能 = 还不该写在这里**;长篇取舍理由 → 代码注释一句
5. **related 必须列全**:它是「改代码 ↔ 改文档」联动的锚点(见下)
6. 标题用中文,文件名/目录用英文小写
7. 文档 tracked 进仓库,随镜像发布——本地改完需部署才在页面生效

## related 联动:部署门禁的反问

部署 skill(cogni-agent-dev-deploy)的 Step 0.7 规定:每次部署合并前,
AI 必须反问「本次提交的代码涉及的功能,是否在功能说明清单里?如果在,
功能说明更新了没有?」——查证方式由 AI 自行决定(diff 比对 related 声明等)。

这道门的目的:**改了功能代码却没同步更新文档**时,把「要不要补」变成
显式决策而不是默认漏掉,防止文档随迭代悄悄腐化失真。反问不阻断,由用户判断
(纯 bug 修复不改行为描述的,记一句理由即可跳过)。

## 页面行为速查

- 路由:`/#/system/feature-docs`(系统设置下),登录即可读,无写入口
- 列表接口 `GET /api/admin/feature-docs`(不含正文,一次性全量索引,
  搜索/目录分组在前端做——量小);详情 `GET .../feature-docs/{doc_id}`
- 「更新于」= 文件 mtime(随镜像发布时间);关联代码以 code 标签展示
